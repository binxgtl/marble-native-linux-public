# Run23 — R2 ION-ownership diagnostic candidate: interface specification (engineering, NOT BOOTED)

Run23 asks one question: **with Run22's proven path unchanged (amplifier switches read back
Disable before the endpoint exists, PDR UP, one GPR `GET_SPF_STATE` through the PID1 endpoint
anchor), can PID1 also own `/dev/msm_audio_ion` (make its node, open it once, hold anchor + guard,
seal both pairs with one filter, census both ION devices by number, release it once at its final
close) and still end in a clean reboot with complete sealed USB evidence that the strict journal
rule accepts?** It is an ownership diagnostic, not an M11 audio PASS and not CP2: no PCM, no
playback, no amplifier enable, no calibration, no gain, no graph, no DSP memory map, no ION ioctl
(no allocation, import, map or hyp-assign), no persist write. Design and evidence:
[docs/m11-r2-ion-ownership.md](../../../docs/m11-r2-ion-ownership.md).

Differences from Run22 (one causal variable plus one evidence fix):

1. R2 ION ownership (runner, `anchor-native/{audio_runtime,gpr_linux}.c`,
   `qualification/ownership/{m11_anchor_owner,m11_anchor_linux}.c`, build flag
   `-DM11_ANCHOR_NATIVE_ION`).
2. Journal records stamped at `journal.sh`'s clock and granularity
   (`anchor-native/journal_time.h`; the Run22 strict-evidence defect). Evidence only.
3. Identity strings `M11R23` / `m11r23` / `Run 23`.

## Transport (relay `scripts/m11/run23/kmsg-relay.c`)

Exactly `scripts/m11/run20/kmsg-relay.c` (protocol M11I3, see run20/PROTOCOL.md) with only:

1. Runtime directory `/run/m11-instrumentation/` instead of `/run/m11/` for `logger.stop`,
   `logger.ready`, `usb.ready`, `logger.done`; the event file is
   `/run/m11-instrumentation/journal` instead of `/run/m11/events`.
2. START payload `run=M11R23 nonce=<32 hex>\n`.
3. `EVENT_RESERVE` = 1 MiB + 64 KiB (journal.sh caps the journal at 1 MiB) and `CAP` = 4 MiB
   (K frames keep `CAP - EVENT_RESERVE`).
4. Nothing else: write-only tty (`O_WRONLY`), no host ACK, same SHA seal, same F frame.

The relay runs as uid/gid 65534 without capabilities (spawned by the runtime with
`NO_NEW_PRIVS`); `next/control journal` chowns `/run/m11-instrumentation` and `/dev/kmsg`, and
`run23/usb` chowns `/dev/ttyGS0` before publishing `usb.ready`.

E stream content = the runner journal (`M11I1 <seq> <time> session ...` records, hex payloads,
written by `record()` and `journal.sh`), terminated by `journal_finish`'s
`M11I1 END <seq> <sha256>` line; `logger.stop` holds the journal byte count (journal.sh).

## Host

`scripts/m11/run23/{receiver.cs, host-reader.ps1, host-observer.ps1, check-capture.py}` derived
from run20: USB parent `USB\VID_1D6B&PID_0104\M11R23`; START regex `run=M11R23`; the terminal
rule `[M11R19 event] FINAL_EVIDENCE` is replaced by: the E stream must be a complete runner
journal accepted by `scripts/m11/instrumentation/evidence.py` journal inspection (contiguous
sequence, valid `M11I1 END` digest). Every other M11I3 rule is unchanged (both digests,
counters, F frame, no W frame for PASS, receiver receipt, clean flush/close, empty serial-error
list).

## Runner (`scripts/m11/run23/runner.c`)

`run22/runner.c` plus, in order:

- after the endpoint bind: wait up to 5 s for `/sys/class/msm_audio_ion/msm_audio_ion/dev` and
  `/sys/class/msm_audio_ion_cma/msm_audio_ion_cma/dev` (each cross-checked against
  `/proc/devices`); `mknod /dev/msm_audio_ion` (0600) only; `m11_audio_bind_ion` (sysfs DEVNAME,
  root 0600 node with one link, no CMA node, census); journal record `ion`. Missing metadata or a
  refused bind holds (breadcrumb `ion_wait` / `ion_bind`), before PDR starts and before any open.
- after a qualified PDR UP: endpoint anchor bind, then at once the ION anchor bind (`/dev/msm_audio_ion`,
  `O_RDWR|O_NONBLOCK`, the boot's only ION open), then `m11_anchor_owner_seal_pairs` over both pairs
  (both nodes unlinked), `m11_audio_attach_anchors`, loan setup including
  `m11_gpr_anchor_attach_ion` (the worker drops the ION pair with `close_range` before its hygiene).
- a boot whose PDR never came UP unlinks both nodes and opens neither.
- after the query: the endpoint final close, then the ION final close (`ion_final_close`), both
  before retire and `stop_adsp`; at the end both anchors must end `REBOOT`.

Kept from Run22: no host-receipt gate (receive-only observer); PID1 breadcrumbs
`<5>M11R23 pid1 step=<name>` on a fresh `/dev/kmsg` fd before every phase; `control amp_gate`
after `usb_start` and before the spawner (only `switches-disabled` admits the query); the PID1
fatal-signal hold. Colours: green query READY, red query error, cyan PDR not UP; BLUE from init.

## Post-run oracle (operator, read-only, after Android returns)

`adb shell cat /proc/cmdline` (`bootinfo.pureason=`, `bootinfo.pdreason=`) and
`adb shell cat /sys/bootinfo/powerup_reason`: `0x40001`/`reboot` = orderly reboot,
`0x20001`/`kpanic` = kernel panic, anything else = classify only.
