# Run22 — GPR diagnostic candidate: interface specification (engineering, NOT BOOTED)

Run22 asks one question: **can the native PID1 runner, with the PID1 endpoint anchor, perform one
GPR `GET_SPF_STATE` query on a never-mapped boot, with both amplifier switches read back Disable
before the endpoint exists, and end in a clean reboot with complete sealed USB evidence?** It is
a GPR diagnostic, not an M11 audio PASS: no PCM, no playback, no amplifier enable, no
calibration, no gain, no graph, no DSP memory map, no persist write.

## Transport (relay `scripts/m11/run22/kmsg-relay.c`)

Exactly `scripts/m11/run20/kmsg-relay.c` (protocol M11I3, see run20/PROTOCOL.md) with only:

1. Runtime directory `/run/m11-instrumentation/` instead of `/run/m11/` for `logger.stop`,
   `logger.ready`, `usb.ready`, `logger.done`; the event file is
   `/run/m11-instrumentation/journal` instead of `/run/m11/events`.
2. START payload `run=M11R22 nonce=<32 hex>\n`.
3. `EVENT_RESERVE` = 1 MiB + 64 KiB (journal.sh caps the journal at 1 MiB) and `CAP` = 4 MiB
   (K frames keep `CAP - EVENT_RESERVE`).
4. Nothing else: write-only tty (`O_WRONLY`), no host ACK, same SHA seal, same F frame.

The relay runs as uid/gid 65534 without capabilities (spawned by the runtime with
`NO_NEW_PRIVS`); `next/control journal` chowns `/run/m11-instrumentation` and `/dev/kmsg`, and
`run22/usb` chowns `/dev/ttyGS0` before publishing `usb.ready`.

E stream content = the runner journal (`M11I1 <seq> <time> session ...` records, hex payloads,
written by `record()` and `journal.sh`), terminated by `journal_finish`'s
`M11I1 END <seq> <sha256>` line; `logger.stop` holds the journal byte count (journal.sh).

## Host

`scripts/m11/run22/{receiver.cs, host-reader.ps1, host-observer.ps1, check-capture.py}` derived
from run20: USB parent `USB\VID_1D6B&PID_0104\M11R22`; START regex `run=M11R22`; the terminal
rule `[M11R19 event] FINAL_EVIDENCE` is replaced by: the E stream must be a complete runner
journal accepted by `scripts/m11/instrumentation/evidence.py` journal inspection (contiguous
sequence, valid `M11I1 END` digest). Every other M11I3 rule is unchanged (both digests,
counters, F frame, no W frame for PASS, receiver receipt, clean flush/close, empty serial-error
list).

## Runner (`scripts/m11/run22/runner.c`)

`anchor-native/runner.c` with: no host-receipt gate (receive-only observer, as Run19/Run20);
PID1 breadcrumbs `<5>M11R22 step=<name>` on its own `/dev/kmsg` fd before every phase (streamed
live as K frames, so a reset localises the last phase); `control amp_gate` after `usb_start` and
before the spawner: the query requires `switches-disabled` (both switches read back Disable),
else hold. Colours: green query READY, red query error, cyan PDR not UP; BLUE from init.

## Post-run oracle (operator, read-only, after Android returns)

`adb shell cat /proc/cmdline` (`bootinfo.pureason=`, `bootinfo.pdreason=`) and
`adb shell cat /sys/bootinfo/powerup_reason`: `0x40001`/`reboot` = orderly reboot,
`0x20001`/`kpanic` = kernel panic, anything else = classify only.
